This is the corporate website of CASES (CaMau Seafood Processing and Service JSC), built on EmDash, a CMS on Astro with a full admin UI. It runs on Cloudflare (D1 + R2) and is bilingual: English at `/`, Vietnamese at `/vi/`.

## Commands

```bash
pnpm dev                                   # Astro dev server (admin at /_emdash/admin)
pnpm build                                 # Production build
pnpm exec astro check                      # Typecheck
node scripts/build-seed.mjs                # Regenerate seed/seed.json from the script
npx emdash seed seed/seed.json --validate  # Validate the seed
npx emdash types                           # Regenerate emdash-env.d.ts from a running site
```

On a fresh database, open `http://localhost:4321/_emdash/api/setup/dev-bypass?redirect=/` once: it applies the seed (schema and sample content) and signs in as a dev admin. A seed is never re-applied to an existing database; after setup, edit content in the admin.

If the dev server dies with exit code 3221226505, "out of memory" or "bad allocation", the machine ran out of memory. Close other apps, or run with `RAYON_NUM_THREADS=1`.

## Structure

| Path | Purpose |
| --- | --- |
| `astro.config.mjs` | `emdash()`, Tailwind v4 (`@tailwindcss/vite`), i18n (`en` default unprefixed, `vi`), fonts |
| `scripts/build-seed.mjs` | **Source of truth for the seed.** Every text is written once as `T(en, vi)`; the script emits an English entry plus a Vietnamese translation linked by `translationOf` |
| `seed/seed.json` | Generated by the script above. Do not edit by hand |
| `src/layouts/Base.astro` | Fixed header, footer, contact slide-over, EN \| VI switch, EmDash head/body wiring |
| `src/pages/` | `index`, `[slug]` for English; `vi/index`, `vi/[slug]` for Vietnamese; `404` per locale. All server-rendered |
| `src/components/blocks/*.astro` | One component per block type, registered in `CasesBlocks.astro` |
| `src/i18n/ui.ts` | UI chrome strings (nav, footer, contact panel, labels) and locale helpers |
| `src/site.config.ts` | Phone, email, address, logo path: facts shared by both languages |
| `src/styles/global.css` | Tailwind theme (the design's exact sky/slate values) and hand-written effects |
| `public/cases-logo.svg` | Company logo (also the favicon and hero watermark) |
| `cases-website 13-5/` | Original static HTML design. Reference only, not built |

## Content model

- `pages` collection: `title` and `content` (a `blocks` field). Slugs: `home`, `about`, `products`, `infrastructure`, `certifications`.
- `products` (68 entries across 6 categories), `certifications` (9, one is table-only), `plants` (5 export-coded plants). Each has English and Vietnamese rows.
- Block types (13): `cases_hero` (layouts `center`, `split`, `glow`, `banner`), `cases_codes`, `cases_reach`, `cases_features`, `cases_timeline`, `cases_values`, `cases_plants`, `cases_tech`, `cases_certs`, `cases_spotlight`, `cases_cert_table`, `cases_catalog`, `cases_cta`.
- `cases_plants`, `cases_certs`, `cases_cert_table` and `cases_catalog` read the `plants`, `certifications` and `products` collections at request time, so editors change those entries rather than the page.
- Menus `primary` and `footer` exist per locale. The footer's "Main Plants" column comes from the `plants` collection.
- Photos: products, plants and technology cards show a dashed "photo" placeholder until an image is uploaded in the admin.

## Rules

- Content pages are server-rendered (`output: "server"`). No `getStaticPaths()` for CMS content.
- Never prefix the default locale (`prefixDefaultLocale`): it breaks `/_emdash/admin`.
- Pass `locale` to every `getEmDashCollection`, `getEmDashEntry` and `getMenu` call; use `toLocale(Astro.currentLocale)`.
- Internal links authored in the CMS go through `resolveHref()` (`src/utils/links.ts`), which sanitizes them and adds the `/vi` prefix.
- Image fields are objects (`{ src, alt }`): render with `<Image image={...} />` from `"emdash/ui"`.
- `entry.id` is the slug (locale-prefixed for `vi`); `entry.data.id` is the database ULID.
- Top-level `select` fields in the seed keep their choices in `validation.options`; repeater sub-fields use `options` directly. A field slug cannot be `status`.
- Tailwind classes must be written out literally; they are not built from variables. The site is dark navy with sky-blue accents, Plus Jakarta Sans for headings and Playfair Display for hero headlines.
- Page copy lives in `scripts/build-seed.mjs` or the admin, never hard-coded in components. UI chrome goes in `src/i18n/ui.ts` in both languages.

## Admin language (Vietnamese)

EmDash 1.4.0 ships no Vietnamese admin catalog, so this project adds one with a pnpm patch: `patches/@emdash-cms__admin@1.4.0.patch` (registered in `pnpm-workspace.yaml` under `patchedDependencies`). It registers locale `vi` and its 3,525-message catalog. The translation source is `i18n/admin-vi.json` (Lingui compiled format, machine-translated, not reviewed by a native speaker). Pick it in the admin under Settings → Language.

When upgrading EmDash, the patch is tied to `@emdash-cms/admin@1.4.0` and will stop applying: run `pnpm patch @emdash-cms/admin@<new>`, re-add the `vi` entries (loader in `dist/loadMessages-*.js`, entry in `dist/locales-*.js`, `dist/locales-manifest.json`, `dist/messages-vi.js`, `dist/locales/vi/messages.mjs`), translate new ids, then `pnpm patch-commit`. Check first whether upstream has added `vi`.

## Known gaps

- The contact form has no server endpoint: it opens the visitor's email app addressed to `salesmanager@cases.com.vn`.
- The footer's Sustainability and Export Policy links point to sections of the Certifications page; there are no dedicated pages yet.
- Privacy and Terms links from the design were dropped because the pages do not exist.
- Wrangler resource ids (D1 database id, R2 bucket) are not created yet. Run `pnpm wrangler login`, then `pnpm deploy`.
